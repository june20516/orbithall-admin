## 지금 어드민에서 가능한가
**불가. 백엔드의 테스트용 토큰 발급 수단이 먼저 필요합니다.**

## 배경
2026-09-28에 Playwright를 도입했지만, E2E는 로그인하지 않은 상태와 백엔드 인증 실패(401·만료) 경로만 다룹니다. Google 로그인은 자동화할 수 없어 테스트가 `AUTH_SECRET`으로 세션 쿠키를 직접 만드는데, 그 안에 넣을 **백엔드가 인정하는 토큰**을 어드민이 만들 방법이 없습니다. 백엔드 JWT 서명 키는 백엔드 소유라 어드민 테스트가 가져다 쓰지 않습니다.

그래서 사이트 목록·상세·수정, 댓글 조회·삭제 같은 정상 흐름과, 클라이언트에서 호출한 Server Action이 401을 받아 로그인 페이지로 보내는 흐름(`ActionResult.loginRequired`)은 아직 브라우저로 직접 확인해야 합니다.

## 작업 범위

### 포함
- 백엔드와 방법 협의: 로컬·테스트 환경에서만 켜지는 테스트 로그인 API 등으로 백엔드 토큰을 발급받는 방법
- 테스트 사용자·사이트 데이터 준비 방법 (현재 로컬 수동 데이터는 사이트 82)
- 스모크 시나리오: 사이트 목록·상세·수정 저장, 댓글 조회·삭제, 클라이언트 Server Action의 401 → 로그인 페이지

### 제외
- CI 구성 (CI 자체가 아직 없음)
